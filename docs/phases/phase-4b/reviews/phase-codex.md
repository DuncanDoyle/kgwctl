**Hold `v0.1.0`.** The release script can let two builds write into the same tag directory, and its published install check can inspect a different binary from the one `go install` just wrote. I would also resolve the selection and JSON contract findings before publishing `v1alpha2`.

### Findings

1. **P1 · Correctness — Concurrent release builds can mix artifacts.** The script checks whether the tag directory is empty, then creates it with `mkdir -p` in a separate step. Two invocations can both pass the check and write to the same `.stage`, archives, and checksum file. One invocation can rewrite archives after the other has checksummed them, or remove the other’s staging files. This breaks D-035’s requirement that the checksums and publish manifest describe the four archives from one build. Claim the tag directory atomically before staging. [hack/release.sh:37](/Users/ddoyle/Development/claude/kgwctl-claude-phase4/hack/release.sh:37)

2. **P2 · Correctness — The release install check can inspect the wrong binary.** The printed command uses fixed `GOPATH` and `GOMODCACHE` directories and leaves `GOBIN` to the caller’s environment or `go env -w` settings. With a configured `GOBIN`, `go install` writes there, while the next command executes `.agents-tmp/release-install/gopath/bin/kgwctl`. That path can contain a binary from an earlier attempt. Use fresh directories and set `GOBIN` to the directory the verification command reads. The scratch-clone checks do not establish R16 for the public tag. [hack/release.sh:114](/Users/ddoyle/Development/claude/kgwctl-claude-phase4/hack/release.sh:114) · [implementation-plan.md:209](/Users/ddoyle/Development/claude/kgwctl-claude-phase4/docs/phases/phase-4b/implementation-plan.md:209)

3. **P2 · Architecture — Adding an agreeing downstream claim can make an exact rule fail selection.** DD-4 tests `IndexCertainty` after xdsview merges agreeing claims. An unset value inherits the claim’s certainty, so an exact metadata claim with an unset `IndexCertainty` already supplies exact rule evidence. If a downstream wrapper adds an agreeing exact-origin claim whose indices are inferred, xdsview’s merge takes `max(unset, inferred)`. `--select exact --rule` then moves the route to `selection.inferred`, even though the original exact evidence is still present. The selection contract needs effective index certainty resolved before that information is lost.
