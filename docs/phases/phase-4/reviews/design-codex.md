## P1 — Correctness and security bugs

1. **Default Envoy captures can contain values sourced from Kubernetes Secrets.** The redactor only removes values for recognized header names. In v2.5.1, `headerModifiers.secretRef` can turn every entry in a Secret into a header. Translation writes those values into ordinary Envoy `HeaderValue` fields, with no provenance for the bundle redactor to use. A custom header carrying an opaque credential therefore survives the default capture. Redact values across the affected mutation structures regardless of header name, and test a Secret-backed custom header with a value that matches no text pattern. 2. **The JWKS exception can preserve key material.** The design exempts `local_jwks` from inline-data redaction and requires it to survive the test. Kgateway accepts inline JWKs and key sets, then serializes them into Envoy’s `inline_string` without projecting them to public keys. A symmetric JWK’s `k` or private JWK parameters can also survive in the original GatewayExtension’s JSON string. Parse both representations and retain only verified public material, or omit the payload. The prior-art notes flag symmetric JWKS, while the threat assessment treats all JWKS as public. ## P2 — Design and plan gaps

1. **Namespace and install scope need a single contract across collectors.** The root binds `-n` as a scalar and already has `--install <ns>/<name>`. The design adds repeatable `-n` and a namespace-only install selector with no rule for multiple installs, failed detection, or conflicting flags. `load.Load` configures no namespace-scoped reads, and raw controller metrics can name Gateways outside the selected namespaces. Define read scope, archive scope, cluster-scoped exceptions, and what happens when install ownership is unknown. Use one resolved scope for every collector and record it in the manifest. 2. **Replica discovery needs a stronger identity than the existing selector.** `SelectPod` matches the literal Gateway name against one Pod label. - **D-024 sets the right ownership boundary, but “verified” needs to qualify a specific claim.** `route_source` identifies an originating route, rule, and match. It carries no proof of which policy won, merged, or produced a filter. A policy condition can verify the controller’s reported result for the target, controller, and generation it actually names.
