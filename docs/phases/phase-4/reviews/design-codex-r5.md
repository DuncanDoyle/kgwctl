**Three P1 findings affect what the bundle includes or omits.** The main issue is that the design treats ownership and discovery scope as independent filters, even though a route’s discovery scope belongs to the install behind its parent.

### P1 · Correctness

1. **An unrelated install can keep an unwatched route.** §3.2 keeps a resource if any selected install watches its namespace. Suppose a `team-b` route points only to install A’s Gateway, A excludes `team-b`, and install B watches `team-b`. `view.Filter` keeps the route because its parent is visible, and the namespace test passes through B. Snellius still records the route as unwatched for A. The bundle would contain the YAML that Call 15 says to omit and list the same route as unwatched. Discovery scope for a route needs to be evaluated against the installs behind its eligible parents. 2. **`--all-controllers` can widen an explicit `-n`.** §3.2 says the flag takes resources and workloads from every namespace. The plan also specifies all workloads and a `Keep` callback that always returns true. The contract needs to preserve that boundary for both flags together, including when a kept route references a Service outside it.
