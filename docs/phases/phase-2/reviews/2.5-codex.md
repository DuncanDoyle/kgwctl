## Findings

1. **P1 · Correctness — A terminal Ctrl-C can discard report bytes and still leave exit 0 or 1.** [internal/app/live.go:153](/Users/ddoyle/Development/claude/kgwctl-claude-phase2/internal/app/live.go:153) runs the findings exit logic after a successful `writeCheck`. If the first Ctrl-C arrives while a timeout report is being written to a Linux terminal with `NOFLSH` disabled, the terminal can discard queued output that the write already counted. The write can still complete successfully, so the user can see an incomplete report and receive the ordinary findings exit. This is a consequence of the Linux terminal implementation, inferred from source. The author’s mid-observation SIGINT run does not exercise it. [Linux terminal signal handling](https://github.com/torvalds/linux/blob/master/drivers/tty/n_tty.c#L991-L1035), [Linux PTY output flushing](https://github.com/torvalds/linux/blob/master/drivers/tty/pty.c#L190-L202).

2. **P1 · Correctness — A partial write with an error exits 1, the same status as a complete report with findings.** [internal/app/live.go:153](/Users/ddoyle/Development/claude/kgwctl-claude-phase2/internal/app/live.go:153) returns the write error directly. If stdout accepts a prefix and then reports an I/O error, for example a full filesystem, `Execute` prints `Error:` and exits 1 regardless of cancellation or findings. This branch predates the diff. It still breaks D-020’s distinction for scripts that use the exit status to decide whether stdout contains a usable report. [internal/app/root.go:218](/Users/ddoyle/Development/claude/kgwctl-claude-phase2/internal/app/root.go:218), [docs/decisions.md:135](/Users/ddoyle/Development/claude/kgwctl-claude-phase2/docs/decisions.md:135).

3. **P2 · Requirements — A first Ctrl-C during output loses the required stderr notice.** [internal/app/live.go:145](/Users/ddoyle/Development/claude/kgwctl-claude-phase2/internal/app/live.go:145) is the last cancellation check. If Ctrl-C arrives after it, during report construction or writing, the report retains `timeout` and the CLI omits `Stopped by Ctrl-C.` even after a successful write. Keeping the serialized stop reason is compatible with writing one document. The missing notice conflicts with the brief’s explicit output-time acceptance assertion, the README, and D-020. [Phase 2.5 brief:37](/Users/ddoyle/Development/claude/kgwctl-claude-phase2/docs/phases/phase-2/phase-2.5-brief.md:37), [README.md:116](/Users/ddoyle/Development/claude/kgwctl-claude-phase2/README.md:116), [docs/decisions.md:133](/Users/ddoyle/Development/claude/kgwctl-claude-phase2/docs/decisions.md:133).
