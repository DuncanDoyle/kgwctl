Two **new P2 issues** arise from the replacement clearance logic:

1. **Pending checks can falsely confirm recovery.**  
   [diff.go:192](/Users/ddoyle/Development/claude/kgwctl-claude-phase2/internal/observe/diff.go:192)

   `ran()` uses `!NotChecked()`, whereas the documented execution predicate requires `ok=true` and no unavailable input. `NotChecked()` explicitly returns false for pending or held checks, including `OK=false`.

   Consequently, finding present → check unavailable/finding lost → check pending without that finding can emit **“checked again”** and **CLEARED**, replace `lostAt` with `clearedAt`, and describe an undecided check as confirmed recovery. Snellius’s xDS restart path supplies a concrete pending/hold state. Require successful execution appropriate to confirming absence; test unavailable → pending → successful recovery separately.

2. **The tracker forgets earlier checks required to confirm clearance.**  
   [diff.go:273](/Users/ddoyle/Development/claude/kgwctl-claude-phase2/internal/observe/diff.go:273)

   `e.ran = r` replaces the recorded set on every model containing the finding. Example: A and B run with finding F; B becomes unavailable while F persists; F subsequently disappears while B remains unavailable. The tracker has forgotten B and marks F cleared.

   This contradicts `docs/output.md`: clearance requires **every check that ran while the finding was present** to run again without it. Preserve the required set across the finding’s presence, and add this three-model regression.
